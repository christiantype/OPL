Lake Opeka · Quick reference

Drop photos in. Pick a base Mode on the right. Sliders + value fields are bidirectional — slide or type a number. Re-roll rolls a fresh seed; Export PNG / SVG renders at the Output size.

Modes

  • Slice — cuts the canvas into parallel strips at any angle; each strip pulls a slice from one of your photos. Sliders: Count, Angle, Variation (uneven widths), Offset / Rotation / Scale jitter, Source pick (Random / In order / Alternating).
  • Glyph — grid sampling where each cell is a typed character or uploaded SVG/PNG. Type your own char or pick a preset; Upload glyph stamps an SVG or PNG at each cell, tinted by the sampled color.
  • Smudge — an ASYNC-style directional drag. The photo's pixels are pulled along one axis from a source line, so detail across the line survives while the smear axis turns to long painterly streaks. Direction (Horizontal / Vertical) · Origin (the source line) · Reach (how far the streak pulls) · Blend (soft photo↔streak transition) · Bands + Jitter + Gap (break it into brushed lanes).
  • Scatter — photos as squares with optional connecting trails. Drag a square on the canvas to move; per-image numeric fields edit it precisely. Each photo gets a subject point auto-detected (saliency + chroma); trails anchor there, not the bounding box.
  • Window — one bold character (or several) carved into the canvas, photo shows through it. Shape · Count · Size · Position jitter.
  • Echo — each photo repeated N times with offset + decreasing opacity. Direction is set by Offset X / Y; Scale step grows or shrinks each echo.
  • Grid — asymmetric magazine grid; cells span varied units, each filled with one photo cover-fit. Density · Asymmetry · Gap.

Effect Layer

A Dot or Glyph overlay whose colors are sampled from the just-rendered base composition. With no points it covers the whole canvas. Click anywhere on the canvas to drop a point — the layer is then confined to those circular pools with the Brush radius + Falloff you set. Drag a point to move; Shift-click or use × in the list to remove.

Tip: turn the base into something visual (Slice / Smudge / Scatter), enable the layer, set Dot size small + Sample blur high → soft halftone fragments that adopt the base colors.

Scatter — Trails

The connective bit. Each photo's subject point gets used as a graph node; trails connect them.

  • Connect — Chain (in add-order) · Near 2 / Near 3 (each photo to its N nearest) · MST (Prim's minimum spanning tree) · All (every pair).
  • Anchor — Square center (geometric) or Subject (line attaches to what the photo is about).
  • Style — Straight · Curved (bows perpendicular) · Dashed · Wavy (sin wave).
  • Color — Solid picker, or Subject gradient where each line gradients from one endpoint's subject color to the other.
  • Subject markers — Dot / Ring / Crosshair stamped on each subject point so the anchors are visible.

Output

Export size is in pixels. PNG rasterizes the full composition (base + effect layer). SVG exports the Effect Layer fragments as vector circles / glyphs when the layer is on. The photographic bases (Slice / Smudge / Scatter / Window / Echo / Grid / Circle / Nest) stay raster — use PNG for those.

Record captures the live canvas to a video — hit Record (or press R) for a 3-second bird-chirp countdown, then it rolls; tweak sliders / re-roll while it runs, and stop to download an MP4.

Filenames include the seed so you can re-find a look later by re-typing the seed (coming soon — for now, screenshot the seed shown top-right).

Shortcuts

  • Drop files anywhere on the window to add photos.
  • Click an image thumbnail to toggle it off / on (without removing).
  • × on a thumbnail removes it; Clear all wipes the source list.
  • Type a number in any value field next to a slider; Enter or Tab to commit.
  • R starts / stops recording the canvas; ⌘Z / ⌘⇧Z undo / redo.

How it works — under the hood

Lake Opeka is one self-contained HTML file — no build step, no libraries, no server. The whole thing (interface, image compositing, color sampling, video recording, storage) is plain JavaScript driving the browser's Canvas 2D API. This page explains how the pieces fit, so you can read the source and change it.

1 · The shape of the program

There is exactly one source of truth: a JavaScript object called state. It holds your images, the current seed, the active mode, and a little settings bag for each mode (slice, smudge, glyph, scatter…).

The data flow is a loop with one direction:

a control changes → write the new value into state → call render() → pixels appear

render() never reads the DOM for values — it only reads state. That means the picture is a pure function of state + your photos: the same inputs always paint the same output. Almost every interesting bug or feature in a tool like this comes down to keeping that promise true.

2 · Seeded randomness (why layouts are reproducible)

Lots of modes place things "randomly" — jittered slice widths, scattered squares, per-band smudge origins. But if that used the real Math.random(), the layout would reshuffle on every repaint, so nudging one slider would scramble everything else.

Instead it uses mulberry32(seed) — a tiny deterministic pseudo-random generator. Seed it with a number and it produces the same stream of "random" values every time. So:

  • While you tweak sliders, the seed is fixed → the layout stays put and only the thing you changed moves.
  • Re-roll simply picks a new seed → a brand-new arrangement.
  • Because the seed is shown top-right, a composition can be recovered later.

Each render starts by calling mulberry32(state.seed) fresh, so the random sequence restarts from the same place every frame.

3 · Drawing: it's almost all drawImage

The Canvas 2D call ctx.drawImage(img, sx,sy,sw,sh, dx,dy,dw,dh) does the heavy lifting everywhere — it crops a rectangle out of a source (the s values) and scales it into a destination rectangle (the d values). Crop, scale, and stretch are all the same call with different numbers.

Cover-fit (filling a box without distortion) is one helper, drawCoverIntoRect: pick the scale = max(boxW/imgW, boxH/imgH) so the image overflows the box on one axis, then center it and let the canvas clip the overflow. It's the same math CSS uses for object-fit: cover.

Two more canvas tools show up a lot: globalCompositeOperation (the blend modes — multiply, screen, difference…) and clipping + masking with destination-in (keep only the pixels that overlap a shape you draw next).

4 · What each mode actually does

  • Slice — rotate the canvas by Angle, then walk across it drawing Count parallel strips. Each strip is one drawImage pulling a slice from a source photo. The RNG jitters each strip's width (Variation) and its offset / rotation / scale.
  • Smudge — the ASYNC drag. First the photo is cover-fit onto an offscreen base canvas. Then, for each horizontal lane, it takes a single 1-pixel column of base at the Origin and stretches it across the whole width: drawImage(base, originX,y, 1,h, 0,y, W,h). That keeps the vertical detail of that column but smears it sideways. A linear-gradient alpha mask (transparent at the Origin, ramping to opaque outward) is applied with destination-in, and the streak is drawn over the untouched photo — so the image stays crisp at the Origin and dissolves into streaks toward the edges. Bands + Jitter just repeat this per lane with different origins.
  • Glyph — lay an invisible grid over the composed image, read the average color of each cell with getImageData, then stamp a character (or an uploaded SVG/PNG silhouette) filled with that color at the cell.
  • Scatter — each photo becomes a square placed in canvas coordinates (drag to move). A subject point is auto-found by scanning the image for the most salient / colorful region. The trails are a little graph drawn over those points — chain, nearest-N, Prim's minimum spanning tree, or all pairs — rendered as straight, curved, dashed, or wavy strokes.
  • Window — draw a big character, then use it as a mask (destination-in) so a photo only shows through the letter.
  • Echo — stamp the same photo N times, each offset a little and faded, for a motion-trail.
  • Grid — generate an asymmetric magazine grid (cells span varied row/column units) and cover-fit one photo into each cell.
  • Circle / Nest — polar compositions: concentric rings / wedges / beads, or nested shrinking frames toward a vanishing point.

5 · The Effect Layer (sampling colors back out)

This is the one feature that reads the canvas after it's drawn. It makes a blurred copy of the current picture, reads its pixels with getImageData, and repaints a dot/glyph grid using those sampled colors — so the overlay always matches whatever is underneath. If you drop points on the canvas, it builds a soft radial mask (pools with falloff) and keeps the overlay only inside them, again via destination-in.

6 · Sliders that read both directions

Every slider has a number beside it that's actually an editable input. Drag the slider and the number updates; type a number and it drives the slider. Internally the displayed value is a friendly 0–10 scale that's mapped to the control's real min/max, so the UI stays consistent even when the underlying range is something odd like 0.05–0.48.

7 · Undo, Sessions, Autosave

A snapshot is just an object recording the value of every control. Undo/redo keep an array of snapshots and a pointer that walks back and forth. Named Sessions and your last setup are stored in localStorage; your actual photos are too big for that, so they live in IndexedDB. Settings are a recipe — reopen the tool and your last look comes back, then you re-add the photos.

8 · Export & Record

PNG re-runs render() into an off-screen canvas at the export resolution and calls canvas.toBlob(). Because every mode sizes itself from the canvas width/height, the 3000px export is the same composition as the on-screen preview, just sharper.

SVG (Effect Layer only) emits real <circle> / glyph vector elements instead of pixels.

Record uses two browser APIs: canvas.captureStream(fps) turns the live canvas into a video MediaStream, and MediaRecorder encodes that stream — into MP4 (H.264) where the browser supports it, WebM otherwise. Hitting Record first runs a 3-second countdown (a Web Audio–synthesized bird chirp per count, with a generated reverb tail — no sound file), and only then starts capturing, so the countdown stays out of the clip. Anything that repaints the canvas while recording — a slider, a drag, a Re-roll — shows up in the video. Stop and the chunks are stitched into a downloadable file.

9 · Why one file?

Keeping the whole tool in a single HTML document means it's portable (open it anywhere), there's nothing to install or build, and the source is the documentation — View Source on this page and everything above is right there to read and tinker with. That's the point: these tools are meant to be taken apart.
