Findings

01

Two shell systems, and the drift lives in onestructural

tool.css (#dock islands) is the clean reference across 16 tools. The ibm.css family is where nearly every inconsistency sits — size dock, export panel, and island styling all vary there.

02

Four orphan tools off the galleryresolved

fractal was a loose shader — now built into a full tool on the shell. The OP/EN trio (open-capture / open-reel / open-slots) is shelled (topbar · subhead · Sessions) and all four are published as OP-LAB-021–024.

03

lake-opeka parameters aren't islandsgap

Its .controls aside never got the island treatment every other tool has, so its rail reads differently.

04

Export isn't fully unifiedby-design → unify

flux, lake-opeka, and open-lab keep custom export instead of the shared format · pixels · print-size · DPI panel every other tool now uses.

05

Island drop-shadow paritypolish

The ibm rail cards (ash / scanner / letter-strings) are bordered cards without the soft float-shadow the tool.css islands carry — so close, not identical.

06

Size-dock & theme are unspecified axesdecide

Several ibm tools have no size dock (likely fixed-aspect — worth confirming vs. omission). Dark- vs light-bodied defaults are split with no shared rule or toggle.
